# Capa UI — módulos reutilizables

Módulos de UI reutilizados entre modos (`modes/play` y `modes/edit`) sin conocimiento directo del modelo de datos, salvo donde se indica.

- **`ui/table.js`**: mesa infinita con pan (arrastrar) y zoom (rueda). Crea estructura con `el` (superficie a insertar en el DOM) y `worldEl` (contenedor interior donde cada modo añade contenido). Completamente genérico, no conoce componentes. Posición/zoom puramente visuales, no persistidos (se reinician al recargar), pero sí estado de módulo (`cameraX`/`cameraY`/`zoom`, fuera de `createInfiniteTable`) para sobrevivir a remontados completos de la mesa (cada `components:changed`/`mode:changed` vuelve a invocar `createInfiniteTable`) — como solo hay una mesa activa a la vez, un único estado de cámara compartido basta. Expone también `fitToBounds(bounds, { padding = 60 })`: reencuadra instantáneamente para que la caja `{ minX, minY, maxX, maxY }` quede visible con margen, capado a `minZoom`/`maxZoom`, o vuelve a vista neutra (`cameraX = cameraY = 0`, `zoom = 1`) si se pasa `null` — la caja la calcula siempre el caller (`getComponentsBounds`), `table.js` no lee `state.js`.
- **`ui/resizeHandle.js`**: utilidad genérica del patrón de redimensionado (manejador esquina inferior derecha). Expone `attachResizeHandle(hostEl, { axis = 'both', getSize, clamp, onResize, onResizeEnd })`: añade `div.resize-handle`, engancha mousedown/mousemove/mouseup sobre `document`, calcula tamaño propuesto según `axis` (`'x'`, `'y'` o `'both'`), lo pasa por `clamp()` (límites del caller), llama a `onResize(size)` en cada movimiento y `onResizeEnd(size)` al soltar. No conoce componentes ni límites propios — reutilizada por `ui/componentList.js`/`ui/resourceList.js` (panel), `ui/componentRenderer.js` (cajas de texto), `ui/tableColumnResize.js` (columnas de tabla). Con `axis === 'both'`, mantener Shift fuerza aspecto 1:1: se lee `e.shiftKey` en cada `mousemove`/`mouseup` (sin listener de teclado propio) y se usa el delta de mayor magnitud entre ancho y alto para ambas dimensiones antes de `clamp()`.
- **`ui/rotationSlider.js`**: utilidad genérica reutilizada, mismo criterio que `ui/resizeHandle.js`. Expone `createRotationSliderField({ label = 'Rotación', value = 0, onChange })` → `{ field, setValue(v) }`: `field` es un `div.modal__field.rotation-field` con slider `<input type="range" min="0" max="360">`, marcas visuales en 0/90/180/270/360 (resaltando la más cercana al valor actual con `.rotation-slider__mark--active`) y campo numérico sincronizado. Imán: constante de módulo `ROTATION_SNAP_THRESHOLD_DEG = 8` — si el valor crudo del slider está a esa distancia o menos de una marca, se fuerza al valor exacto de la marca antes de propagar. `setValue(v)` resincroniza el control desde fuera sin disparar `onChange`. Reutilizado por `ui/imageAdjustModal.js`, `ui/cardShapeModal.js` y `ui/cardTextBoxModal.js`.
- **`ui/tableColumnResize.js`**: ajuste manual de ancho de columnas de tabla, reutilizado por `ui/componentList.js`/`ui/resourceList.js`. Expone `attachColumnResizing(table, columns, widths, onChange)` — `columns`: array ordenado de claves que coincide con `data-col` de cada `<th>`; `widths`: objeto persistido `{ [columna]: pxNumber }` o `null`; `onChange(newWidths)`: callback al soltar, con el objeto completo. Engancha `attachResizeHandle` (`axis: 'x'`) por `<th>`, añade clase `column-resize-handle` (línea de borde de columna, no grip de esquina). En el primer movimiento de cualquier columna de una interacción, fija `table.style.tableLayout = 'fixed'` con el ancho real de todas las columnas a la vez, para que fijar una no descuadre las demás. Sin límite máximo por columna, solo mínimo interno (`60px`).
- **`ui/componentRenderer.js`**: sí conoce el modelo de componente. Expone `getComponentsBounds(components)`: caja envolvente `{ minX, minY, maxX, maxY }` (o `null` si ninguno), usando los mismos defaults que el renderizado (`x`/`y` = `100`, `width`/`height` mínimo `40×24px`) — alimenta `fitToBounds` de `ui/table.js` desde `ui/editModeToggle.js`. Expone `renderComponentsOnTable(worldEl, components, { onSelect, onToggleSelect, selectedIds = new Set(), onMove, onResize, canMove = () => true, onContextMenu, identifyMode, liftOnDrag = false, showLockIndicator = false } = {})`: limpia y redibuja cada componente soportado sobre `worldEl`, posicionado según `x`/`y`.
  - `selectedIds`: `Set<string>` de ids seleccionados — cada tipo resalta con `<tipo>--selected` cualquier componente cuyo id pertenezca al conjunto; el manejador de redimensionado (si se pasa `onResize`) solo se ofrece cuando el conjunto tiene tamaño 1 y lo contiene.
  - `onToggleSelect(component, event)` recibe también el evento nativo de `click`, para que el caller lea `event.ctrlKey`/`event.metaKey` y decida si el toggle es aditivo o de reemplazo.
  - `identifyMode` (`'tooltip' | 'label'`, sin default): cómo se muestra "qué es" cada componente sin abrirlo, vía helper `formatComponentIdentifier(component)` (`"<Tipo>: <id>"`). `'tooltip'`: atributo `title` nativo en el contenedor. `'label'`: `<span class="component-id-label">` hijo del contenedor, anclado esquina superior izquierda vía CSS, visible solo en hover/selección.
  - **Regla para cualquier tipo que recorte su propio contenido visual** (imagen con zoom, texto que desborda, forma circular, etc.): el `overflow: hidden` debe aplicarse a un contenedor **interno** dedicado, nunca al contenedor exterior — el exterior es donde se añade `.component-id-label`, que no debe recortarse nunca (puede sobresalir del componente por diseño). Patrón: `div` interno con `position: absolute; inset: 0; overflow: hidden` (más el `border-radius` que corresponda) envuelve solo imagen/texto/patrón de fondo; el contenedor exterior mantiene etiqueta, borde y listeners de selección/arrastre/redimensionado sin `overflow: hidden`.
  - **`onContextMenu(component, event)`**: si se pasa, cada tipo añade listener `contextmenu` sobre su contenedor exterior (`preventDefault` + `stopPropagation`) que lo invoca.
  - **`showLockIndicator`** (`false` por defecto): si `true` y `component.bloqueado !== 'ninguno'`, añade al contenedor exterior la insignia de `createLockBadge()` (helper local, análogo a `createIdentifierLabel`).
  - **`showHiddenIndicator`** (`false` por defecto): análogo, para `component.oculto`, con `createHiddenBadge()` (icono ojo tachado), esquina inferior derecha (convive con candado).
  - Antes de dibujar, ordena internamente una copia de `components` por `order` descendente y dibuja en ese orden: cada `appendChild` posterior queda por encima visualmente, así que el `order` más alto (el "de fondo") se dibuja primero, el `order = 1` el último (encima de todos) — el array recibido no necesita venir ya ordenado.
  - Render por tipo — ver `02-component-types.md` para propiedades específicas; aquí solo mecánica común de interacción: si se pasa `onSelect`, doble-click abre la modal (`onSelect(component)`); si se pasa `onToggleSelect`, click único la selecciona/deselecciona; si `selectedIds.has(component.id)`, clase `<tipo>--selected`; si se pasa `onResize` y `selectedIds` tiene tamaño 1, manejador de redimensionado (ambos ejes, libre salvo Shift = 1:1); si se pasa `onMove` y `canMove(component)` es `true`, componente arrastrable (clase `<tipo>--movable`, arrastre en pantalla convertido a coordenadas del mundo dividiendo por el zoom actual), invoca `onMove(component, x, y)` al soltar.
  - **`liftOnDrag`** (`true`): cada bloque de arrastre trae el nodo al final de `worldEl` (al frente visual, sin tocar `order`) y añade estado transitorio `lifted` (`beginDragLift`) al `mousedown`, lo quita (`endDragLift`) al soltar antes de `onMove` — simula que el componente se levanta (desplazamiento fijo + sombra) mientras dura el gesto. Puramente visual y temporal, no persiste ni modifica `order` real (el reordenamiento de "Subir al mover/interactuar" se dispara aparte, en `onMove` de `playMode.js` al soltar).
  - Reutilizado por `modes/play/playMode.js` (con `onMove`/`canMove` limitando arrastre a `bloqueado === 'ninguno'`; `identifyMode: 'tooltip'`; `liftOnDrag: true`; sin `onSelect`/`onToggleSelect`/`onResize`) y `modes/edit/editMode.js` (los cuatro originales, `canMove` propio limitando a `bloqueado !== 'todos'`; `identifyMode: 'label'`; `onToggleSelect` comparte función `toggleSelect` con la fila del panel; sin `onCartaFlip`, sin `liftOnDrag`).
- **`ui/contextMenu.js`**: menú contextual genérico posicionado junto al cursor, reutilizable para cualquier click derecho de la app (distinto de `createAddMenu` de `ui/resourceList.js`, que es desplegable fijo bajo un botón). Expone `openContextMenu({ x, y, generalItems, specificItems = [], interactionItems = [], description, onClose })`.
  - `generalItems`/`specificItems`: `{ icon, label, onClick, disabled }[]`, o `{ label, select: { options: { value, label }[], disabled, onChange } }[]` para fila con `<select>` inline (primer uso: "Añadir a etiqueta" del menú de Modo Edición, ver `04-modes.md`) — elegir opción real invoca `onChange(value)` y cierra el menú; sin opciones o `disabled: true`, `<select>` deshabilitado.
  - Pinta primero, si se pasa, línea de descripción (`description`), luego sección general, y solo si `specificItems` no vacío, separador + sección específica; por último, si `interactionItems` no vacío, sección informativa fija de solo lectura (`{ label, value }[]`) con qué hace cada tipo de click sobre el componente.
  - `description`: `{ main: string, extra?: string }` — línea de solo lectura al principio (antes de `generalItems`), separada por línea si se pasa, `main` en negrita, segunda línea tenue con `extra` si se pasa.
  - Se añade a `document.body` con `position: fixed` en `(x, y)`, reajustado tras insertarse para no salirse de la ventana. Comportamiento singleton (estado de módulo con el menú abierto, si lo hay, cerrado automáticamente antes de abrir otro).
  - Se cierra al click fuera (`mousedown` en `document`), ESC (listener propio del módulo, no usa `ui/globalShortcuts.js` que solo reconoce DOM de modales) o al elegir fila; en los tres casos invoca `onClose` si se pasó, antes de desmontar.
  - En `modes/play/playMode.js`, `onContextMenu` pasa `description` calculada de `formatComponentIdentifier(component)` (`main`) y, según `type`, un `extra` diferenciador: nº de resultados posibles para `'dado'`, tamaño `"AAxBB"` para `'tableroSimple'`, nº de cartas para `'mazo'`, sin `extra` para el resto.
  - `interactionItems` parte de constante de módulo `interactionsByType` (array `{ label, value }[]` fijo por `type`: "Clic izquierdo"/"Doble clic izquierdo"/"Clic derecho"); función local `getInteractionItemsFor(component)` sustituye el `value` de "Clic izquierdo" por `"Ninguno"` cuando `core/interactions.js` → `isInteractionActive(component, key)` es `false` para la interacción de click de ese `type` — el resto de filas y tipos sin interacción programada se devuelven sin cambios.
- **`ui/componentTypeModal.js`**: modal previa al alta, sin tabs — lista de los 8 tipos disponibles (radio buttons: `'texto'`/`'tableroSimple'`/`'tableroPersonalizado'`/`'dado'`/`'documento'`/`'carta'` con etiqueta "Carta/Ficha"/`'mazo'`), con "Cancelar"/"Aceptar". Al aceptar, `modes/edit/editMode.js` crea el componente con `createDefaultComponent(type)`, lo añade al estado, abre `ui/componentModal.js` sobre ese componente ya existente para configurarlo. Sin desplegable de tipo dentro de esa modal.
- **`ui/componentModal.js`**: modal de creación/edición, dos tabs ("Generales" y "Específicas"), siempre sobre componente ya existente (recién creado o presente). Ver `01-component-model.md` para los campos de "Generales" y `02-component-types.md` para los campos específicos por tipo. Pie con "Cancelar" y "Aceptar" (deshabilitado si el id no es válido), "Eliminar" siempre presente. Exporta `createDefaultComponent(type)`, `DEFAULT_BOARD_PROPERTIES`, `DEFAULT_TABLERO_PERSONALIZADO_PROPERTIES`, `DEFAULT_CARTA_PROPERTIES`, `DEFAULT_MAZO_PROPERTIES`.
  - **`workingComponent`**: copia **superficial** (`{ ...component }`) — campos de primer nivel (`bloqueado`/`mostrarTooltip`/`subirAlMoverInteractuar`/`etiquetaIds`, tab "Generales") son descartables con "Cancelar" porque viven en esa copia; pero `workingComponent.properties` es la **misma referencia** que `component.properties` — cualquier cambio dentro de `properties` (Proporción, diseño de cara vía `ui/visualEditorModal.js`, bloques de "Pegar estilo") se aplica de inmediato sobre el objeto real del estado, no solo al aceptar.
- **`ui/styleClipboardSelectionModal.js`**: modal de selección al pulsar "Copiar estilo" desde `ui/componentModal.js`. Expone `openStyleClipboardSelectionModal({ component, onAccept })`: checklist de un único grupo fijo de 4 elementos (Generales, Proporción, Cara frontal, Cara trasera), todos marcados por defecto, con nota auxiliar por ítem. No reutiliza `ui/elementSelectionModal.js` (pensada para colecciones dinámicas con `id`/label) — construye marcado propio reutilizando las clases BEM `.element-selection-group*` para heredar el lenguaje visual sin duplicar CSS. Botón "Copiar" deshabilitado si no queda ítem marcado. `onAccept(selection)` recibe `{ generales, proporcion, caraFrontal, caraTrasera }` (booleanos). Convenio a seguir si se extiende "Copiar/Pegar estilo" a otros tipos.
- **`ui/styleClipboardErrorModal.js`**: modal de error al pegar estilo, abierta cuando `validateStyleClipboardForPaste` devuelve incidencias. Expone `openStyleClipboardPasteErrorModal(incidencias)`: cabecera de error (`modal__header--error`/`modal__error-icon`) combinada con tabla, reutilizando **sin CSS propio** las clases `.import-report-modal`/`.import-report-modal__table`, tres columnas (Elemento/Referencia/Detalle). Solo botón "Cerrar" — el pegado es todo o nada, no hay "continuar sin".
- **`ui/boardPatternModal.js`**: sub-modal sin tabs para el fondo "Color y patrón" de tablero simple — color, forma de casilla (cuadrada/hexagonal), filas/columnas (1–50). Opera sobre copia de trabajo, aplica a `properties` solo si se acepta.
- **`ui/boardImageModal.js`**: sub-modal análoga para fondo "Imagen" — galería en grid (miniatura + nombre) de recursos `type === 'imagen'`, selección única con click (doble click selecciona y confirma directamente, equivalente a click + Aceptar); sin recursos, "No hay imágenes disponibles" con "Aceptar" deshabilitado. Sin función de subida (ya existe en panel "Recursos"). Parámetro opcional `title` (default `"Configurar fondo — Imagen"`) para personalizar título sin duplicar el módulo (usado también por cada cara de `'carta'` desde `ui/visualEditorModal.js`).
- **`ui/imageAdjustModal.js`**: editor reutilizable de ajuste de imagen (posición, zoom, giro sobre forma cuadrada/circular/redondeada), agnóstico del tipo de componente. Expone `openImageAdjustModal({ shape, width, height, resource, adjustment, transparencia, onAccept, faces, initialFocusKey })`.
  - Sin tabs: uno o varios "stages" con forma recortada (máscara `overflow: hidden`, `border-radius` según `shape` — `'circular'` → `50%`, `'redondeada'` → `8px`, o `clip-path` para hexagonal/triangular) a tamaño de previsualización que preserva la proporción `width`×`height` real. Dentro de cada stage con recurso, `<img>` + control de zoom (`<input type="range" min="100" max="300">`) sincronizado con cuadro de texto (`<input type="text">`, clampeado a `[100, 300]`, valor no numérico se descarta).
  - **Control de rotación** (`ui/rotationSlider.js`, `createRotationSliderField`): opera sobre `focusedKey` igual que Zoom/Transparencia, resincronizando (`setValue`) al cambiar de cara enfocada.
  - **Slider "Transparencia"** (`modal__field`, `min="0" max="100"`, sincronizado con cuadro de texto igual que "Zoom"): solo se pinta si algún entry trae `transparencia !== undefined` (`hasTransparencia`); opera sobre `focusedKey` igual que Zoom/90º; aplica `opacity = 1 - transparencia/100` sobre la vista previa en tiempo real; al aceptar, se incluye en el resultado devuelto (por-`key` en modo `faces`, o directo en modo single-stage) solo si `hasTransparencia`.
  - Sin `faces`: un stage anónimo con `shape`/`width`/`height`/`resource`/`adjustment`/`transparencia` de nivel superior; `onAccept(adjustment)` recibe el ajuste de ese stage — llamador: `ui/cardShapeModal.js` (`adjustImageBtn`), para la transparencia de imagen de una `Forma`.
  - Con `faces` (array `{ key, label, shape, width, height, resource, adjustment }`): un stage por entrada, orden fijo del array, `label` como título siempre visible; estado interno por `key` (`{ zoom, posX, posY, rotation }`) y `focusedKey` (inicializado a `initialFocusKey`, o el primer `key` con `resource`). Listeners de arrastre y controles Zoom/Rotación operan sobre `focusedKey`, resincronizando al cambiar foco; `mousedown` sobre el mask de una cara con `resource` no enfocada cambia `focusedKey` e inicia arrastre en el mismo gesto (el arrastre no tiene en cuenta el ángulo de rotación actual). Cara sin `resource`: hueco vacío, sin listener, nunca `focusedKey`. "Aceptar" invoca `onAccept` una vez con `{ [key]: { zoom, posX, posY, rotation } }` de todas las entradas; "Cancelar" descarta todo sin invocar `onAccept`. Llamador de este modo: `ui/visualEditorModal.js` (`openAdjustSession`) para `cara.transparenciaImagen`.
  - Exporta `applyImageAdjustStyle(imgEl, adjustment, boxWidth, boxHeight)`: aplica el resultado final — `object-fit: cover` + `object-position` sobre el `<img>`, con `width`/`height`/`top`/`left` en píxeles calculados siempre sobre `boxWidth`×`boxHeight` (rotación estricta: el tamaño de la imagen según zoom no cambia con `rotation`, puede dejar huecos en las esquinas al girar, el recorte de la máscara/marco oculta lo que sobra); con `rotation !== 0`, añade `transform: rotate(${rotation}deg)` con `transform-origin` en el centro del marco real. Reutilizada por `ui/componentRenderer.js` (pintado final de cada cara de `'carta'` y cada `Forma` con imagen) y por `ui/visualEditorModal.js` (previsualización en el editor).
- **`core/cardProportions.js`**: módulo de datos puro. Expone `CARD_PROPORTIONS`, `getProporcionRatio(value)`, `getCartaShapeCss`/`isRectShape`/`getHexInnerClipPath`/`getTriangleInnerClipPath` (ver `02-component-types.md`). `CARD_DESIGN_WIDTH` (300): constante histórica, conservada solo porque la migración `migrateCartaMedidasReales` (ver `06-persistence-build.md`) necesita el ancho de referencia histórico para cartas guardadas con el sistema de lienzo de diseño anterior a los píxeles reales.
- **`ui/visualEditorModal.js`**: modal grande ("Editor visual", `.card-editor-modal`) para diseñar una o varias caras de un componente, abierta desde tab "Específicas" de `ui/componentModal.js` ("Editar diseño de la carta" / "Editar diseño del tablero"). Expone `openVisualEditorModal({ component, title, faces, showProporcionSelector = true, borderStyle = 'simple', onAccept })`.
  - `faces`: `[{ key, label }]` — dos entradas `caraFrontal`/`caraTrasera` para `'carta'`; una entrada `cara`, `label: null`, para `'tableroPersonalizado'`.
  - `showProporcionSelector`: oculta desplegable de proporción/forma y checkbox "Esquinas redondeadas" cuando el tipo no tiene proporción configurable (`'tableroPersonalizado'`).
  - `borderStyle` (`'simple' | 'bisel'`): línea simple (`'carta'`) o bisel de dos tonos (`'tableroPersonalizado'`, vía `shadeColor`).
  - Opera sobre copia de trabajo (`working[key]` por cara, más `proporcion`/`esquinasRedondeadas` si `showProporcionSelector`) aplicada al componente solo si se acepta — `onAccept(result)` recibe `{ [proporcion, esquinasRedondeadas,] ...facesByKey }`.
  - Toolbar superior con desplegable de proporción si aplica (cambia copia de trabajo, no borra `textBoxes`, solo recalcula tamaño del lienzo). Cuerpo con una columna por cara: lienzo escalado desde el tamaño de diseño de la cara (`getFaceDesignSize()`: siempre `{ width: working.designWidth, height: working.designHeight }`, inicializados al tamaño real actual del componente al abrir — con `showProporcionSelector`, cambiar "Proporción" recalcula `designHeight = designWidth / getProporcionRatio(nuevaProporcion)`, mantiene fijo el ancho real) con factor `previewScale` único (constante `CANVAS_MAX_SIDE = 380`; `.card-editor-modal` con `max-width: min(1500px, 95vw)`).
  - Imagen de fondo (si `imagenResourceId`) pintada con `applyImageAdjustStyle`; `textBoxes` posicionados/dimensionados según valores de diseño × `previewScale`, alineación/margen vía `core/textBoxLayout.js`, cada uno arrastrable (delta de pantalla convertido a "unidades de diseño" dividiendo por `previewScale`) y redimensionable (`ui/resizeHandle.js`, `getScale: () => previewScale`); doble click abre `ui/cardTextBoxModal.js`. Botones por cara: "Elegir imagen…" (`ui/boardImageModal.js`), "+ Cuadro de texto".
  - Botón único "Ajustar imagen…" (deshabilitado si ninguna cara de `faces` tiene imagen); invoca `openImageAdjustModal` una vez con array `faces` construido del mismo `faces` del editor (posiciones fijas) e `initialFocusKey` (primera cara con imagen) — el propio popup gestiona el foco internamente sin cierre/reapertura. Al aceptar, `onAccept(adjustments)` guarda `adjustments[key]` en `working[key].ajusteImagen` de cada cara; cancelar no aplica nada.
  - Footer "Cancelar"/"Aceptar" (invoca `onAccept(result)`).
- **`ui/cardTextBoxModal.js`**: sub-modal sin tabs para editar `textBox` de una cara, abierta con doble click desde `ui/visualEditorModal.js`. Expone `openCardTextBoxModal({ textBox, onAccept, onDelete })`: contenido (`textarea`), tipografía (botón que reutiliza `ui/diceFontModal.js`, lógica ya genérica pese al nombre del fichero), bloque "Posición del texto en el cuadro" (dos `.align-group` para alineación horizontal/vertical, fila de 4 campos numéricos para márgenes — `parseInt` + `Math.max(valor, 0)`), tamaño (unidades de diseño) y color. Opera sobre copia de trabajo, aplicada al `textBox` original solo si se acepta. Footer "Eliminar" (quita el cuadro y cierra), "Cancelar", "Aceptar".
- **`ui/diceFontModal.js`**: sub-modal análoga a `ui/boardImageModal.js` para `fuenteResourceId` de `'dado'` — lista (no grid) de recursos `type === 'tipografia'`, cada uno con nombre y muestra de texto renderizada con esa tipografía (`ui/fontFaceRegistry.js`, `fontFamilyFor`), selección única con click; sin ninguna, "No hay tipografías disponibles" con "Aceptar" deshabilitado.
- **`ui/diceResultModal.js`**: modal "ver resultado en grande" de `'dado'`, abierta con doble click en modo juego — sin tabs, muestra `properties.resultadoActual` a tamaño grande, botón "Cerrar".
- **`ui/helpIcon.js`**: componente genérico de ayuda contextual. Expone `createHelpIcon({ text, html })` (mutuamente excluyentes) → `span.help-icon` con "?": `text` con menos de 200 caracteres muestra tooltip (`span.help-icon__tooltip`) en hover; en cualquier otro caso (`html` presente, o `text` ≥200 caracteres), click abre modal reutilizando el patrón `modal-overlay`/`modal` de `ui/componentModal.js` (botón "Cerrar"), contenido vía `textContent` o `innerHTML`. No conoce el modelo de componente. Usado por `ui/componentModal.js` (ayuda del desplegable "Bloqueado").
- **`ui/editModeToggle.js`**: expone `renderModeSwitcher` (botón "Entrar en modo edición") y `renderEditToolbar` (barra fija "Salir del modo edición", "Guardar", "Exportar"/"Importar" — ver `06-persistence-build.md`). Ambas añaden, en el extremo derecho de su contenedor, botón icono-solo "Ajustar zoom" (mismo SVG en ambos sitios), handler calcula `getComponentsBounds` y llama a `fitToBounds` de `ui/table.js`. "Guardar" pide nombre de fichero con `prompt()` nativo; "Exportar"/"Importar" no (ver más abajo).
- **`ui/elementSelectionModal.js`**: no es modal en sí, sino bloque de UI reutilizado por `ui/exportSelectionModal.js`/`ui/importSelectionModal.js`.
