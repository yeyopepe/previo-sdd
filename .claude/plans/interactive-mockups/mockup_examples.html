Ejemplos de uso — el framework de notas sobre un mockup real

El mockup de ejemplo es el lanzador "Bloc de notas" y una hoja. No hay pin ni modo "armado": un clic simple selecciona el elemento y la barra (solo iconos) se desplaza junto al cursor. El ➕ crea la nota — general si no hay selección, o preguntando con un mini-menú si la hay.

Escena 1 · Clic en un elemento → barra al cursor → ➕ → mini-menú

Escena 4 · Guardar y cierre del ciclo en pv-new / pv-fix

Al pulsar 💾 Guardar

1. Descarga design_bloc-notas.html con las notas en #mnote-data:

<script type="application/json" id="mnote-data">
[
 {"id":"n1","kind":"linked",
  "selector":"button.launcher__new-btn",
  "text":"Más grande, quitar el (3)"},
 {"id":"n2","kind":"linked",
  "selector":".sheet__header",
  "text":"Falta icono de arrastrar"},
 {"id":"n3","kind":"general","selector":null,
  "text":"Unificar el amarillo"}
]
</script>

2. El usuario reemplaza el archivo y vuelve al chat.

3. En el paso de validación visual, pv-new / pv-fix / extend-entry.md detectan #mnote-data con notas, y por cada una:

  • aplican el cambio al design_*.html (vía la skill de mockups con action: edit, o edición directa si es menor);
  • eliminan la nota resuelta de #mnote-data;
  • resumen en la respuesta qué se cambió por cada nota.

4. Se vuelve a presentar la maqueta ya corregida para confirmar.

Round-trip: si el usuario reabre el archivo antes de volver al chat, el framework lee #mnote-data y rehidrata las 3 notas (contadores y panel). Si una nota vinculada ya no encuentra su elemento (mockup editado entre medias), baja al panel como desvinculada (borde rojo) sin perder el texto.
