## ⭐New

- 📂**Maintenance skills**:
  - **`/pv-review-doc-tech` reorganizes the technical documentation** — periodically rereads every `docs.tech` folder in full and reorganizes its content (moving, grouping, consolidating duplicates, fixing misfiled `**Area**` tags) without ever deleting a fact, rewriting a sentence, or adding new content; it regenerates `INDEX.md` automatically and flags anything it isn't safe to decide on its own (e.g. a namespace conflict) for the user.
  - **`/pv-review-architecture` proposes code reorganizations** — checks the real source code against a fixed, language-agnostic design checklist (separation of concerns, file/class size, SOLID, DRY, KISS, coupling/layering, naming, folder structure) and produces a numbered list of pure reorganization proposals (move/split/merge/rename), never adding or changing functional code. For each proposal the user accepts, it asks individually whether to record it as a noted idea (`pv-todo`) or a documented change (`pv-new`) and creates it accordingly.

## ✏️Changed

- 📂**Mockups and design files reorganized**:
  - **Mockups now live in their own `mockups/` subfolder** — `design_*.html`/`design_*.txt` files generated by `pv-new`/`pv-fix` are written to `{changesDir}/inProgress/{xxxx}/mockups/` instead of loose in the entry's root, keeping mockup files separate from the entry's other documents.
  - **Navigation and data files were renamed, dropping the `design_` prefix** — `design_navigation_*.md` and `design_data_*.md` are now `navigation_*.md` and `data_*.md`, staying loose in the entry root (they aren't mockups) to distinguish them clearly from the `mockups/` subfolder's contents.
  - **`pv-todo`'s demote flow carries the new layout over** — demoting a change (`/pv-todo change <xxxx>`) now copies the entire `mockups/` subtree as-is (tagged with a note that it's frozen reference material, not a live design) and preserves `navigation_*.md`/`data_*.md` files under their new names.
  - **`pv-how`'s consistency check reads both new locations** — validating a change/fix's documents before analysis now reads the `mockups/` subfolder and any loose `navigation_*.md`/`data_*.md` files as two distinct sources, with no fallback to the old loose-in-root layout or the retired `design_` prefix.
- 📂**Template bracket syntax fixed everywhere it could leak**:
  - **Framework templates now spell out how to strip `[[[...]]]` markers** — every skill that fills a template (`pv-do`, `pv-new`, `pv-fix`, `pv-todo`, `pv-internal-workflow`, `pv-internal-doc-features`) now states explicitly that `[[[...]]]` is template-only syntax that must never survive into a generated file, with a worked example of unwrapping the label.
  - **`pv-update` detects and fixes leftover bracket syntax** — a new `marker-literal:*` check catches a `description.md`/`plan.md` that still carries the raw `**[[[Name]]]**`/`## [[[Full description]]]` syntax instead of the unwrapped label, and repairs it automatically by stripping just the brackets.
- **Mockups now fall back to the real code when the style bible has a gap** — when generating an HTML or ASCII mockup, if `docs.tech.styleBibleDocDir` doesn't cover a needed element, the mockup skills now look for the real styling/conventions already in the app's source code instead of defaulting straight to a neutral placeholder; anything reused this way is reported back as a "style gap found" so the caller can flag it as a documentation task instead of silently absorbing it.
- **`pv-status` reports the mockup file count separately** — the terminal detail card now shows a dedicated `mockups: N` line (count of files under the entry's `mockups/` subfolder) alongside the existing "extra files" count, which no longer includes mockup files.
- **`pv-update` migrates entries to the new mockup/file layout automatically** — two new checks, `legacy-loose-mockups:*` and `legacy-design-prefix:*`, detect `inProgress`/`implemented` entries still on the old layout (mockups loose in the entry root, or navigation/data files still carrying the `design_` prefix) and fix them: creating `mockups/` and moving the files in, or renaming files to drop the retired prefix.
